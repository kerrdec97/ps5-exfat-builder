# Interface translations

The native app ships the sixteen interface languages of the legacy Python
edition. This note records how the mechanism works, what is and is not
translated, the coverage per language, and how to correct a translation.

## 1. Mechanism

* **Source text is the key.** Every user-visible string in `src/app/**` goes
  through `tr("…")` — `QObject::tr` in `Q_OBJECT` classes, `fw::tr`
  (`app/i18n/I18n.h`) elsewhere — with the English text as the lookup key and
  `%1 …` placeholders kept verbatim. The context is ignored, like the legacy
  `_()`: one English text has one translation everywhere.
* **`fw::i18n::JsonTranslator`** (`app/i18n/JsonTranslator.{h,cpp}`) is a
  `QTranslator` whose table comes from a JSON file compiled as a Qt resource,
  `:/i18n/<code>.json` (`app/i18n/i18n.qrc`). A missing key returns a null
  string, so Qt falls back to the English source; a deliberately empty
  translation (the plural suffixes `s`, `ies`, `y`) returns an empty non-null
  string. No Qt Linguist tooling (`.ts`/`.qm`, `lupdate`, `lrelease`) is used.
* **Settings** are translated at display time: engine `SettingDef`s stay
  English (they are also the stored schema), and `fw::i18n::localized(def)`
  returns a copy with label, description, unit, file filter and choice labels
  looked up through the translator. Section and group names are translated
  with `fw::i18n::trs()` where they are shown; the keys used for lookups,
  storage and demo states stay English.
* **Installing a language**: `fw::i18n::install(QCoreApplication*, code)` at
  start-up (`main.cpp`), from `general.language` or the `--language <code>`
  command-line option. `"system"` resolves through
  `QLocale::system().uiLanguages()`; an unknown or unsupported code (and `en`)
  leaves the English source in place. Arabic also sets
  `Qt::RightToLeft` as the application layout direction, which mirrors the
  sidebar, header, cards and forms.
* **Languages** (`core/Languages.h`): `en`, `zh`, `de`, `fr`, `es`, `pt`,
  `ja`, `ko`, `ru`, `ar`, `it`, `nl`, `pl`, `tr`, `th`, `vi`, `id` — the
  legacy list, in the legacy order, shown by their native names.

## 2. The setting

`general.language` (section General, group Language, enum, restart
required). Choices: *System language* and each language by its native name.

The default is **English**, not the system language. The translations below
are machine-made and unreviewed; a user who wants one opts in, and a
reviewer who finds a mistake can switch back in a page they can read. The
legacy key `language` is imported (`addLegacyKey`): the code before `_` or
`-`, lowercased, `en`/`en_us` → `en`, unknown codes are skipped.

Takes effect when the app restarts (no live retranslation: pages build their
texts once).

## 3. What stays in English

* **Engine messages**: job results, error messages, log lines, dependency
  details and tool output come from `src/core`, `src/engines`, `src/connect`
  and the external tools, and are not translated. They are also what a user
  pastes into a bug report, so one wording serves everyone.
* **Identifiers**: product and tool names (FPKG, PFS, PlayGo, ShadowMount+,
  MicroMount, Fakelib, Autoloader, `param.json`, `prospero-pub-cmd.exe`),
  licence identifiers, credits, keyboard shortcut keys, setting keys,
  section/group lookup keys, format names and units such as `GB`, `MiB`,
  `512 bytes`, the language names themselves, and the specimen strings of
  the FTP diagnostics.
* **Strings assembled by the engines** (for example `klogsrv at %1:%2`,
  `zftpd (%1)`, `SITE AVAIL: %1`) that quote protocol output.

## 4. Language files

`src/app/i18n/<code>.json`, UTF-8, English text as the key:

```json
{
  "language": "de",
  "name": "Deutsch",
  "direction": "ltr",
  "status": "machine-translated, unreviewed",
  "note": "…",
  "translations": {
    "Build image": "Image erstellen",
    "%1 free on %2.": "%1 frei auf %2."
  }
}
```

The files were generated for this release by machine translation and have
**not been reviewed by native speakers**; the header says so, the About page
says so under *Translations*, and corrections are welcome: edit the file,
keep the English key and every `%n` placeholder, and send it to
[@kerrdec97](https://github.com/kerrdec97) on GitHub (the legacy app asked
the same). Where the English text matched a legacy table entry, the legacy
translation was reused.

## 6. Tests and screenshots

`tests/app/tst_i18n.cpp` (offscreen, 24 cases): the language list matches
the legacy one; per language, the file parses, its header is complete,
every key is a current source string, placeholders are preserved, only the
plural suffixes are empty, and the first-screen set is present; the coverage
report; translator lookup and fallback (missing key → source, empty value →
empty); legacy `language` import; the main window started in German and in
Arabic (sidebar items, settings labels and buttons translated, layout
direction right-to-left for Arabic). `FW_I18N_DUMP=<file>` writes the source
list, `FW_I18N_COVERAGE=<file>` the table above.

Screenshots in a language: `FW_DATA_DIR=<tmp> FW_OFFLINE=1
QT_QPA_PLATFORM=offscreen "exFAT Image Builder" --language de
--screenshot-pages <dir>`. German (long words), Japanese (CJK glyphs, needs
a CJK font on the machine — IPAGothic on the build container) and Arabic
(right-to-left) were rendered for every page and demo state and checked for
clipping; the fixes that came out of it (wrapped setting labels, empty-state
captions, badges in narrow cards, the settings pane height) apply to every
language.

## 7. Not done

* No live retranslation: a language change needs a restart.
* Translations are unreviewed machine output; quality varies, and terms
  (dump, image, backport, mount) were kept technical rather than localised.
* Engine messages, logs and tool output stay in English by design.
* Plural forms use the legacy `%1 game%2` suffix scheme (`s`/`ies`/`y` →
  empty), which reads awkwardly in languages without an `-s` plural; the
  translations rephrase where possible (`%1 Spiel(e)`).
